# Схема БД создаётся с нуля, старые базы не поддерживаются

Схема базы данных описана одним блоком `CREATE TABLE IF NOT EXISTS` (`main/database.ts`, `PRAGMA user_version = 1`): `groups`, `players`, `group_memberships`. Историю миграций v1–v3 (таблицы `classes`/`students`) не сохраняем: файл базы удаляется, приложение при первом запуске создаёт свежую схему.

Так сделано, потому что приложение в разработке и реальные данные пользователей ещё не накапливаются; тащить миграции ради переименований дороже, чем начать с чистого листа. Отвергнутая альтернатива: миграция v4 с `ALTER TABLE ... RENAME` — оставила бы мёртвые шаги v1–v3 навсегда.

Следствие: любое несовместимое изменение схемы оформляется правкой этого блока с подъёмом версии и удалением старого файла базы; о несовместимости пишем в ADR. Перед удалением базы предупреждаем пользователя.
