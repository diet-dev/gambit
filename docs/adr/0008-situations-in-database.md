# Ситуации хранятся в базе, а не в коде

Набор учебных шахматных ситуаций (группы + позиции с комментариями) переехал из захардкоженного массива в renderer в таблицы `situation_groups` и `situations` (миграция v4). Порядок задаётся плотными порядковыми номерами `sort_order`; позиция каждой ситуации уникальна (`fen UNIQUE`), название уникально внутри группы. Renderer получает данные по IPC `situations:list`, дефолтная ситуация — первая по сортировке, отдельного флага у неё нет.

Так сделано, потому что пополнение набора не должно требовать релиза: данные правятся в базе, интерфейс подхватывает их при запуске. Отвергнутые альтернативы: строковые slug-идентификаторы из старого массива (нигде, кроме дефолта, не использовались); веса с зазорами вместо порядковых номеров (перенумерация дешевле, чем поддержка дыр).

Следствие: миграция v4 засеивает текущий набор во все базы; добавление CRUD-редактирования ситуаций в интерфейсе становится отдельной задачей поверх готового хранилища.
