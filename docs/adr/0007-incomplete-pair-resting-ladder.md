# Неполная пара хранит слот отдыхающего в лестнице раунда

Раунд хранит полную лестницу игроков: сыгранные пары плюс **неполные пары** — строки `round_pairs` с пустым соперником (`player2_id IS NULL`) и пустым исходом (`result IS NULL`), по одной на каждого отдыхающего. Неполная пара занимает позицию в лестнице: отдыхающий после чётного раунда стоит во главе (доска 0), хвостовой — после последней пары. Лестница следующего раунда восстанавливается из строк прошлого: внутри полной пары игроки меняются местами по итогу (`swapFor`), неполная пара переносит игрока как есть. Отдыхающий сохраняет своё место в рейтинге — первый остаётся первым, последний последним; никакие эвристики «куда вернуть отдыхавшего» не нужны.

Так сделано, потому что раньше отдыхающие не хранились: генератор восстанавливал их вычитанием пар из состава группы и возвращал в лестницу по одному (`find`), из-за чего при двух отдыхающих (чётный раунд, чётный состав) игроки выпадали из турнира насовсем. Отвергнутые альтернативы: выводить всех отдыхающих по правилу чётности без хранения (не решает потерю позиции при пропусках нескольких раундов); хранить лестницу отдельной таблицей (дублирует пары).

Следствие: миграция v3 пересоздаёт `round_pairs` с nullable-полями и CHECK-констрейнтом `((player2_id IS NULL) = (result IS NULL))` и очищает данные раундов; `RoundPairsPreview` отдаёт `restingPlayerIds` списком; форма раунда показывает всех отдыхающих.
