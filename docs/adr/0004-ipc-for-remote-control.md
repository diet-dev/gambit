# IPC между `main` и `renderer` введён для удалённого управления

Для управления доской с телефона `main` поднимает локальный HTTP+WebSocket сервер и через IPC (`remote:position`, `remote:move`, `remote:server-info`) передаёт позицию и ходы в `renderer`. Renderer остаётся единственным источником истины о правиле и позиции; `main` не знает шахмат и лишь ретранслирует сообщения. Это пересматривает границу из `ADR 0002` («IPC для игры не используется»): она была верна, пока не понадобился доступ к ресурсу — сетевому порту, который есть только у `main`.

Так сделано, потому что порт может слушать только `main`, а правила и состояние обязаны оставаться в одном месте; ретрансляция через IPC — минимальная плата за это. Отвергнутая альтернатива: держать в `main` собственную копию позиции и применять ходы телефона локально — избавляет от IPC, но дублирует правила (вразрез с `ADR 0001`) и открывает дорогу к рассинхрону двух досок.

Следствие: IPC-протокол удалённого управления нужно держать типизированным и синхронным с доменом; при добавлении новых ресурсов (`main`) границу допустимо расширять, но источником истины о позиции по-прежнему остаётся renderer.
